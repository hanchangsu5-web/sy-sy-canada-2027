🎨 UI / 디자인 원칙

모든 페이지는 하나의 통일된 디자인 시스템(Design System)을 따른다.

공통 디자인 요소

  • ✔ 동일한 Header와 Footer 사용
  • ✔ 공통 색상(Color Palette) 유지
  • ✔ 동일한 카드(Card) 디자인 사용
  • ✔ 공통 버튼(Button) 스타일 사용
  • ✔ 동일한 폰트 및 글꼴 크기 체계 유지
  • ✔ 일관된 아이콘 스타일 사용
  • ✔ 페이지 간 동일한 여백과 정렬 유지

디자인 목표

사용자가 새로운 페이지를 열더라도 하나의 서비스 안에 있다는 느낌을 받을 수 있도록 전체 사이트의 디자인을 통일한다.

📱 반응형 원칙

모든 페이지는 다양한 화면 크기에서 동일한 사용 경험을 제공해야 한다.

  • ✔ Desktop
  • ✔ Laptop
  • ✔ Tablet
  • ✔ Mobile

새로운 기능을 추가할 때는 PC 화면뿐 아니라 모바일 화면에서도 자연스럽게 동작하는지 반드시 확인한다.

🗺 여행지도 원칙

여행지도는 본 프로젝트의 핵심 기능(Core Feature)이다.

필수 기능

  • ✔ Day별 일정 보기
  • ✔ 이동 경로(Route)
  • ✔ 장소 핀(Pin)
  • ✔ 장소 대표 사진
  • ✔ 장소 설명
  • ✔ 추천 체류 시간
  • ✔ 주차 정보
  • ✔ 화장실 정보
  • ✔ 방문 순서
  • ✔ Google Maps 길찾기 연결
  • ✔ 일정 페이지와 연동

향후 확장 기능

  • □ GPS 현재 위치
  • □ 방문 완료 체크
  • □ 여행 후 사진 연결
  • □ 여행 통계
  • □ 즐겨찾기
  • □ 오프라인 지도 지원

💰 가계부 원칙

가계부는 단순한 계산기가 아니라 여행 예산을 종합적으로 관리하는 기능이다.

관리 항목

  • ✔ 총 예산
  • ✔ 카테고리별 지출
  • ✔ 카드 결제
  • ✔ 현금 사용
  • ✔ 환율 적용
  • ✔ CAD / KRW 동시 표시
  • ✔ 일자별 지출
  • ✔ 가족별 사용 금액
  • ✔ 통계 및 그래프

모든 금액은 정확성을 우선으로 하며, 입력과 확인이 쉽도록 설계한다.

📸 사진 관리 원칙

사진은 여행의 기록이며, 여행 전부터 여행 후까지 하나의 흐름으로 관리한다.

관리 방향

  • ✔ 장소별 사진 관리
  • ✔ Day별 사진 정리
  • ✔ 여행지도와 연동
  • ✔ 일정과 연동
  • ✔ 대표 사진 지정
  • ✔ 여행 후 앨범 기능 확장

🤖 ChatGPT 작업 원칙

ChatGPT는 단순히 코드를 생성하는 도구가 아니라, 프로젝트의 설계와 품질을 함께 관리하는 개발 파트너의 역할을 수행한다.

기본 원칙

  • ✔ 기능 구현 전에 프로젝트 구조를 먼저 검토한다.
  • ✔ 기존 코드와의 호환성을 항상 고려한다.
  • ✔ 프로젝트 전체의 디자인 일관성을 유지한다.
  • ✔ 유지보수가 쉬운 구조를 우선한다.
  • ✔ 사용자가 쉽게 이해하고 적용할 수 있는 코드를 제공한다.
  • ✔ 코드에는 필요한 설명과 적용 위치를 함께 제공한다.

개발 원칙

  • ✔ 임시 구현을 제안하지 않는다.
  • ✔ 이미 완성된 구조를 불필요하게 다시 작성하지 않는다.
  • ✔ 새로운 기능은 기존 구조를 해치지 않는 방식으로 추가한다.
  • ✔ 장기적인 확장성을 고려하여 설계한다.
  • ✔ 기능보다 안정성과 일관성을 우선한다.

🌿 Git 관리 원칙

모든 개발 내용은 Git을 통해 관리하며, 의미 있는 변경 단위로 Commit을 작성한다.

개발 순서

  1. 설계
  2. HTML 작성
  3. CSS 작성
  4. JavaScript 작성
  5. 브라우저 테스트
  6. 모바일 확인
  7. Git Commit
  8. Git Push

Commit 원칙

  • ✔ 하나의 기능 단위로 Commit 한다.
  • ✔ Commit 메시지는 변경 내용을 명확하게 작성한다.
  • ✔ 테스트 완료 후 Push 한다.

🚫 하지 않는 것

프로젝트의 품질을 유지하기 위해 다음 사항은 지양한다.

  • ❌ 임시 구현 후 나중에 다시 만드는 개발
  • ❌ 중복 코드 작성
  • ❌ 페이지마다 다른 디자인 적용
  • ❌ 사용하지 않는 코드 방치
  • ❌ 의미 없는 변수명 및 함수명 사용
  • ❌ 기능별 파일 구분 없이 작성
  • ❌ 테스트하지 않은 상태로 Git Push
  • ❌ 프로젝트 구조를 고려하지 않은 기능 추가

🚀 최종 목표

SY & SY Canada 2027은 단순한 여행 홈페이지가 아니다.

여행을 준비하고, 여행 중 활용하며, 여행이 끝난 후에도 오랫동안 추억을 보관할 수 있는 우리 가족만의 디지털 여행 플랫폼을 만드는 것이 이 프로젝트의 궁극적인 목표이다.
